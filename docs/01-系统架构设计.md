## 组件交互流程

### 1. 用户登录流程
```
前端页面 → 输入用户名密码
    ↓
Axios POST /api/auth/login/
    ↓
Django认证后端 (JWT)
    ↓
返回 JWT Token + 用户信息
    ↓
前端存储Token (localStorage)
    ↓
后续请求携带Authorization Header
```

### 2. 文档创建流程
```
前端点击"新建文档"
    ↓
选择文档类型 (富文本/表格)
    ↓
Axios POST /api/documents/
    ↓
Django创建Document记录
    ↓
返回文档ID和初始数据
    ↓
前端跳转到编辑器页面
```

### 3. 实时协作流程
```
用户A编辑文档
    ↓
Tiptap/Luckysheet触发onChange事件
    ↓
前端通过WebSocket发送操作
    ↓
Django Channels接收并广播
    ↓
其他在线用户收到操作
    ↓
本地应用操作并更新视图
```

### 4. 文件上传流程
```
前端选择文件
    ↓
FormData POST /api/files/upload/
    ↓
Django接收文件并保存到磁盘
    ↓
创建File记录到数据库
    ↓
返回文件信息
    ↓
前端显示上传成功
```

### 5. 文档分享流程
```
前端点击"分享"
    ↓
输入目标用户和权限
    ↓
Axios POST /api/shares/
    ↓
Django创建Share记录
    ↓
可选: 发送站内通知
    ↓
前端刷新分享列表
```

## 技术选型说明

### 为什么选择Django而不是Node.js?
- **成熟稳定**: Django是企业级框架，有完善的ORM和Admin
- **安全性**: 内置CSRF、XSS、SQL注入防护
- **生态丰富**: DRF支持RESTful API，Channels支持WebSocket
- **开发效率**: Admin后台可直接用于管理功能
- **维护成本**: Python代码可读性好，易于维护

### 为什么选择Luckysheet而不是OnlyOffice?
- **轻量级**: 纯前端实现，无需额外部署服务
- **易于集成**: 可直接嵌入Vue项目
- **局域网友好**: 不依赖外部服务
- **成本低**: 开源免费，部署简单
- **注**: OnlyOffice功能更强大但部署复杂，适合后期升级

### 为什么选择PostgreSQL而不是MySQL?
- **JSON支持**: 更好的JSON字段支持（用于文档内容存储）
- **事务处理**: 更强的事务一致性
- **扩展性**: 支持更多高级特性（如全文搜索）
- **开源**: 完全开源，无商业限制

## 扩展性考虑

1. **水平扩展**:
   - 数据库读写分离
   - Redis集群
   - 负载均衡（多台应用服务器）

2. **存储扩展**:
   - 文件存储可迁移至MinIO/S3
   - CDN加速静态资源

3. **性能优化**:
   - 数据库查询优化（索引、缓存）
   - 静态资源压缩
   - 操作日志异步写入

## 安全性考虑

1. **认证授权**: JWT Token + 权限检查
2. **数据传输**: HTTPS（局域网内可选）
3. **文件上传**: 文件类型检查、大小限制、病毒扫描（可选）
4. **SQL注入**: Django ORM自动防护
5. **XSS防护**: 前端编辑器内容转义
6. **CSRF防护**: Django内置
